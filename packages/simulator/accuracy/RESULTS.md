## Method

Each case is one transaction with two separately captured halves in `packages/core/fixtures`. The input half is a pre-send `ethrex_simulateFrameTransaction` response (trace included) and the captured stake and reputation reads (`skandha_explorer_listReputation`; an address the page does not list reads as unstaked). The simulator runs with `createSimulator({ explorer: false, estimate: false })`, so it cannot read the node's admission record or ask the sidecar's estimator. The only node answer it sees is the ethrex simulation. The held-out half is what a node did with the same transaction: a sidecar send or estimate result, an ethrex send result, or an explorer admission record. Halves are matched by transaction identity (sender, nonce keys, nonce, frames) and by hash, ignoring signatures and fees. A prediction matches when the admit or reject verdict agrees for that mempool and, for a rejection, the rule agrees. Rule names on both sides come from the same parser (`rules.ts`), so a parser bug would not show up here; the parser has its own tests. Estimator outcomes that say nothing about the sidecar's rules (placeholder limits, the public gas cap, a missing signature) are dropped, as `check.ts` drops them. A prediction whose source is `model` comes from our local rule model and no node said it: it is unverified until the sidecar confirms it. Only transactions with both halves count. Everything else is listed under Excluded. The case count is small because the fixtures were captured to document node behaviour, not to pair pre-send simulations with outcomes.
